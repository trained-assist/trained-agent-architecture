# Доменные истории

Работа конкретных профессий поверх базовых историй ([USER](USER.md)). Каждая доменная история предполагает, что базовые уже выполняются: диалог (U-01…U-06), подтверждение внешних действий (U-29), подключения (U-28), расписание (U-22).

Формат тот же: кто → ценность → шаги → «готово, когда» → этап. В новом плане доменная работа начинается с I04 (инструменты на тестовых провайдерах), первый пилот — HH (P26). Для остальных доменов пилота в плане нет ⚠.

## Рекрутинг

### REC-01. Вакансия и критерии

**Кто:** рекрутер. **Ценность:** критерии подбора задаются словами или берутся из текста вакансии; вакансии не смешиваются.

1. Подключаю HH, вижу свои вакансии, выбираю активную.
2. Задаю критерии словами или прошу извлечь из текста вакансии; дополняю без потери прежних.
3. Переключаюсь на другую вакансию — у неё свои критерии и история.

**Готово, когда:** при одной вакансии она выбрана сама; критерии и просмотренные кандидаты привязаны к вакансии; дискриминационные критерии не принимаются.
**Этап:** I04 · P14 → I08 · P26.

### REC-02. Оценка откликов

**Кто:** рекрутер. **Ценность:** вижу лучших сразу, с обоснованием по каждому критерию.

1. «Оцени отклики» — прогресс для большого числа.
2. Вердикт подходит / частично / нет, с обоснованием.
3. Топ-N и фильтр «прошли всё»; сменил критерии — предложение пересчитать.

**Готово, когда:** провал обязательного критерия — отказ; без полного резюме — явная ошибка, а не выдуманная оценка; повторная оценка перезаписывает, а не дублирует; честное «никто не прошёл».
**Этап:** I04 · P14 → I08 · P26.

### REC-03. Холодный поиск

**Кто:** рекрутер. **Ценность:** нахожу тех, кто не откликался, и не вижу одних и тех же людей повторно.

1. «Прогрей базу по вакансии» — поиск, оценка, страница просмотра.
2. Сохраняю поиск, повторяю его вручную или по расписанию.
3. Отмечаю «не интересен» — больше не показывается.

**Готово, когда:** просмотренные не возвращаются (и после перезапуска); ошибка доступа не выдаётся за «0 результатов»; платные контакты не открываются без явной просьбы.
**Этап:** I07 · P22 → I08 · P26 (это пилот плана).

### REC-04. Переписка с кандидатами

**Кто:** рекрутер. **Ценность:** сообщение доводится до нужного тона словами, уходит ровно одобренный вариант.

1. «Напиши приглашение» — черновик.
2. Правлю словами: короче, менее официально, в нашем стиле.
3. Массовое персональное приглашение или отказ по шаблону.
4. «Отправляй» — уходит последний одобренный вариант.

**Готово, когда:** ничего не уходит без подтверждения; если кандидат ответил за это время — предупреждение; повторной отправки нет (U-29).
**Этап:** I08 · P25–P26.

## Фриланс

### FL-01. Из слов клиента — к вердикту и ТЗ

**Кто:** фрилансер. **Ценность:** из сбивчивого описания получаю разложенное ТЗ и обоснованное «брать или нет».

1. Присылаю описание, файл или скриншот — создаётся проект.
2. Разбор: факты, требования, допущения, решения; уточняющие вопросы.
3. Вердикт «берём / не берём» с рисками.
4. ТЗ: подробное для исполнителя и короткое для клиента; точечные правки.

**Готово, когда:** сырой диалог не попадает в ТЗ; допущения не выдаются за факты; короткое ТЗ — не сокращение длинного.
**Этап:** ⚠ пилота в плане нет (после I04).

## Продажи на выставках

### EXPO-01. Выставка → сайт с целевыми компаниями

**Кто:** консультант по продажам. **Ценность:** по ссылке на выставку получаю опубликованный каталог участников с отмеченными целевыми.

1. Даю ссылку на выставку.
2. Система находит участников, обогащает данными компаний, проверяет реестры, отмечает целевые.
3. Получаю ссылку на сайт и отчёт с цифрами.

**Готово, когда:** без ИНН — не целевая; санкционная или недействующая — не целевая, с пометкой; неизвестная выручка — «ближняя», а не исключённая; каталог не найден — честная ошибка; цифры отчёта сходятся с сайтом.
**Этап:** ⚠ пилота в плане нет (после I04, I07).

## Речь

### SP-01. Текст из любого аудио

**Кто:** любой пользователь. **Ценность:** голосовое, файл или ссылка превращаются в текст одним способом; дальше — участники, конспект звонка, поиск по старым расшифровкам.

1. Присылаю голосовое, аудиофайл или ссылку.
2. Получаю текст или понятную ошибку (видео — через разбор видео).

**Готово, когда:** пустой текст или отказ модели не выдаются за результат; повторная обработка того же файла не оплачивается дважды; чужой ключ не используется.
**Этап:** I03 · P11 (голосовые) + I04.

## Инженерная доставка

### ENG-01. «Почини / сделай» — до проверенного выпуска

**Кто:** владелец профиля. **Ценность:** просьба превращается в процесс, который заканчивается проверенным выпуском, а не «вроде сделал».

1. Формулирую цель со ссылкой на репозиторий.
2. Вижу план шагов, подтверждаю.
3. Идут шаги: разбор → реализация → проверки → PR → слияние → выпуск.
4. Проверка живого сценария.
5. Закрытие с доказательствами.

**Готово, когда:** план не исполняется до подтверждения; объективные проверки делает код, а не мнение модели; без доказательств закрыть нельзя.
**Этап:** I07 · P24.

### ENG-02. Прогон тестов в облаке

**Кто:** владелец репозитория, агент. **Ценность:** полный прогон тестов ветки без своей машины и без знания CI.

1. Один раз: «настрой прогон в облаке».
2. «Прогони ветку» — зелёный или красный с упавшими тестами и хвостом журнала.

**Готово, когда:** повторная настройка ничего не ломает; новый прогон той же ветки отменяет старый; ничего не сливается и не выпускается.
**Этап:** I07 · P24.

### ENG-03. Новый инструмент навыка — до живого вызова

**Кто:** владелец продукта. **Ценность:** один запуск доводит новый инструмент до настоящего вызова в рабочей сессии.

1. Цель и репозиторий.
2. Заготовка, тест, PR с проверками.
3. Выпуск; инструмент виден в новой сессии.
4. Настоящий вызов.

**Готово, когда:** «слито, но в сессии нет» — не успех; успех по подделке — не успех; нет тестового окружения — шаг блокируется с задачей владельцу, а не пропускается.
**Этап:** I04 · P13 + I07 · P24.
