## 3. Правила ведения юзер-стори отныне

1. **Канонический домен — этот репозиторий.** Новые и правленные юзер-стори живут в [`stories/`](../stories/README.md) (с 30.09, ревизия историй); детальные сценарии поведения — в `scenarios/<domain>/`; `sources/` остаётся снапшотом с provenance (правится только новым импортом с обновлением manifest — [scenarios/README §Копирование](../scenarios/README.md)).
2. **Формат:** цель/ценность для юзера → сценарий → статус = `решение | в работе | план` + **дата + pinned-ревизия** → машинно-проверяемая приёмка → что НЕ запрещает (как в Core 01/02).
3. **Противоречия — сюда или в issue,** не молчаливой правкой стори в разных репо.
4. **Перед новой фичей** — сверка с этим аудитом и со сценариями RC/CH/SS; после закрытия находки — отметить статус здесь.
5. **Решения владельца** (голос/чат) фиксируются в целевом сценарии с датой — как в RC §2, иначе они снова становятся «скрытыми».

## 4. Ограничения аудита

Не проверялись: фактический прогон тестов, прод-поведение, веб-репозиторий кроме ACCEPTANCE/reconnect-доков (только чтение), новые доки, появившиеся в architecture-repo в тот же день (CODE-BASELINE, IMPLEMENTATION plan) — они пересекаются темой, но правились параллельными сессиями; пересечения отмечены в PR на ревью.
